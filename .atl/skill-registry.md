## Architecture Notes

- **Multi-tenancy**: `communities` table, Postgres Row-Level Security. `withClient(fn, options)`
  in `server/api/src/services/postgresClient.ts` requires an explicit scope:
  `inCommunity(id)` or `unscoped(reason)` — no unsafe default. Two DB roles: `DB_APP_USER`
  (RLS-scoped) and `DB_UNSCOPED_USER` (BYPASSRLS, small pool, used only for
  auth/admin/catalogs). Never connects as `POSTGRES_USER` (superuser bypasses RLS).
- **Query layer**: centralized in `server/api/src/services/queries.ts`. Community-scoped
  queries carry `AND ($n::uuid IS NULL OR community_id = $n::uuid)` with the community
  parameter always last; `npm run check-sql` (from `server/api`) cross-checks call-site
  parameter counts against query definitions (TypeScript can't catch this since
  `client.query` takes `unknown[]`).
- **Validation layer**: `server/api/src/services/validations.ts`, Zod schemas + async
  parse/safeParse helper functions per domain type.
- **Code comments in `server/api` source are written in Spanish** (JSDoc-style block
  comments observed in `postgresClient.ts`, `queries.ts`). Match this convention for
  existing-file edits in that package; new cross-project docs/specs still default to English
  per the SDD language contract.
- Reference doc for multi-tenancy: `MIGRACION-COMUNIDADES.md` (Spanish, full migration
  narrative).
